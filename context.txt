# MODELO DE DATOS Y RELACIONES
El modelo analítico está construido bajo una arquitectura de Esquema en Estrella (Star Schema).
**Relaciones Estructurales (Origen 1 -> Destino N):**
- Todas las tablas de dimensión (prefijo `Tabla_`, `Maestro_Fuente`) filtran la tabla de hechos `Leads_Contacts` (Relación 1 a Varios, Dirección Única).
- `Calendario[Date]` -> `Leads_Contacts[Fecha creación]` (Relación Activa principal).
- `Calendario_[Año][Date]` -> `Leads_Contacts[Fecha creación]` (Relaciones Inactivas, que se activan dinámicamente mediante las medidas DAX usando `USERELATIONSHIP`).

## 1. TABLA PRINCIPAL DE HECHOS (FACT TABLE)
**`Leads_Contacts`**: Contiene el registro unificado de todos los Posibles Clientes (Leads) y Contactos (Contacts).

*Columnas Físicas Principales:*
- `Correo electrónico`: Identificador único del estudiante.
- `Nombre` / `Apellidos`: Datos personales de identificación.
- `Tipo de registro`: Define categóricamente si la fila es "Leads" o "Contacts".
- `Particular o Grupo`: Categorización del tipo de cliente.
- `Fecha creación`: Fecha de entrada al sistema CRM.
- `Curso`: Curso académico de interés (ej. 2024/2025, 2025/2026).
- `Ciudades de interés` / `Residencias de interés`: Preferencias geográficas del lead.
- `Ciudad actual` / `Residencia actual`: Ubicación actual de procedencia del estudiante.
- `Residencia escogida`: Destino final adjudicado (cuando aplica).
- `Origen/Campaña Posibles Clientes` / `Fuente de Posible Cliente`: Datos de trazabilidad de marketing y captación.

*Columnas Calculadas (Lógica de limpieza y transformación):*
- `Origen_Agrupado` / `Fuente_Agrupada`: Agrupa la alta cardinalidad de orígenes y fuentes en macro-categorías clave de negocio.
- `Residencias_interes_corregido`, `Residencias_actual_corregido`, `Ciudad_actual_corregido`, `Curso_corregido`: Versiones saneadas de las columnas originales (sustituyen valores nulos o en blanco por "Sin info").
- `Ciudad_deinteres_corregido`: Agrupación de limpieza que etiqueta datos atípicos bajo la categoría "Otros".

## 2. TABLAS DE DIMENSIÓN (LOOKUP TABLES)
Tablas que contienen valores únicos. Su función es normalizar el modelo y permitir el filtrado estandarizado de las métricas.
- **`Tabla_Ciudad_Actual`**: Catálogo único de las ciudades de procedencia de los estudiantes.
- **`Tabla_Ciudad_Interés`**: Catálogo único de las ciudades donde los estudiantes buscan residencia.
- **`Tabla_Curso`**: Catálogo único de los años académicos (ej. 2024/2025).
- **`Tabla_Residencia_Actual_CONTACTS`**: Catálogo único de las residencias actuales asociadas a los contactos.
- **`Tabla_Residencia_Escogida_LEADS`**: Catálogo único de las residencias finales asignadas.
- **`Tabla_Residencia_Interés`**: Catálogo único de las residencias preferidas por los leads.
- **`Tabla_Origen` / `Tabla_Fuente_PC`**: Catálogos únicos de canales de marketing y fuentes de adquisición.
- **`Maestro_Fuente`**: Tabla de homologación que mapea el campo `Fuente_Leads` hacia la categoría `Fuente_Agrupada`.
- **`Glosario`**: Diccionario estático con definiciones de los Indicadores Clave de Negocio (KPIs).

## 3. TABLAS TEMPORALES
- **`Calendario`**: Dimensión de fechas maestra, continua y estándar. Mantiene la relación activa principal.
- **`Calendario_[Año]`** (ej. `Calendario_2024`, `Calendario_2025`, `Calendario_2026`): Calendarios específicos aislados por año. Mantienen relaciones inactivas con la tabla de hechos y se usan en DAX para forzar comparativas anuales cruzadas filtrando datos concretos de cada año.
- **`Calendario_Comparacion`**: Tabla de fechas auxiliar con el campo `Date_COMPARACION` diseñada para aislar rangos de fechas específicos y calcular incrementos o variaciones porcentuales vs periodos previos.

## 4. MEDIDAS Y KPIs (LÓGICA DAX)
Todas las métricas base operan contando correos electrónicos únicos (`DISTINCTCOUNT`) para evitar duplicidades, filtrando por `Tipo de registro`. La lógica de las fórmulas extraídas del modelo es la siguiente:

### MÉTRICAS DE LEADS

LEADS = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Leads", REMOVEFILTERS(Tabla_Ciudad_Actual))

LEADS Seleccionados = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), FILTER(Calendario, Calendario[Date] IN VALUES(Calendario[Date])), Leads_Contacts[Tipo de registro] = "Leads")

LEADS Comparación = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), FILTER(ALL(Calendario[Date]), Calendario[Date] >= MIN(Calendario_Comparacion[Date_COMPARACION]) && Calendario[Date] <= MAX(Calendario_Comparacion[Date_COMPARACION])), Leads_Contacts[Tipo de registro] = "Leads")

LEADS [Año] = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Leads", Leads_Contacts[Curso] = "[Año]/[Año+1]", REMOVEFILTERS(Calendario_[OtrosAños]), USERELATIONSHIP(Calendario_[Año][Date], Leads_Contacts[Fecha creación]))

LEADS Incremento = [LEADS Seleccionados] - [LEADS Comparación]

LEADS Incremento [Año2]vs[Año1] = [LEADS Año2] - [LEADS Año1]

LEADS % Variación_2Fechas = DIVIDE([LEADS Seleccionados], [LEADS Comparación]) - 1

LEADS % Variación [Año2]vs[Año1] = DIVIDE([LEADS Año2], [LEADS Año1]) - 1

LEADS Previous Year Dinámico = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Leads", REMOVEFILTERS(Tabla_Ciudad_Actual), KEEPFILTERS(Tabla_Curso[Curso] = CursoAnterior))

LEADS % Variación_PreviousYear = DIVIDE([LEADS Seleccionados], [LEADS Previous Year Dinámico]) - 1

### MÉTRICAS DE CONVERSIÓN (CR) Y GLOBALES
CR CantidadRegistros [Año] = 
    CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Contacts", Leads_Contacts[Curso] = "[Año]/[Año+1]", Leads_Contacts[Particular o Grupo] = "Particular", REMOVEFILTERS(...), FILTER(Calendario_[Año], ...), USERELATIONSHIP(Calendario_[Año][Date], Leads_Contacts[Fecha creación])) 
    + 
    CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Leads", Leads_Contacts[Curso] = "[Año]/[Año+1]", REMOVEFILTERS(...), FILTER(Calendario_[Año], ...), USERELATIONSHIP(Calendario_[Año][Date], Leads_Contacts[Fecha creación]))

CR Convertidos [Año] = CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Contacts", Leads_Contacts[Curso] = "[Año]/[Año+1]", Leads_Contacts[Particular o Grupo] = "Particular", REMOVEFILTERS(...), FILTER(Calendario_[Año], ...), USERELATIONSHIP(Calendario_[Año][Date], Leads_Contacts[Fecha creación]))

CR ConversionRate [Año] = DIVIDE([CR Convertidos Año], [CR CantidadRegistros Año], 0)

CR Variación [Año2]vs[Año1] = [CR ConversionRate Año2] - [CR ConversionRate Año1]

GLOBAL CantidadRegistros = 
    CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Contacts", Leads_Contacts[Particular o Grupo] = "Particular", FILTER(Calendario, ...), USERELATIONSHIP(Calendario[Date], Leads_Contacts[Fecha creación])) 
    + 
    CALCULATE(DISTINCTCOUNT(Leads_Contacts[Correo electrónico]), Leads_Contacts[Tipo de registro] = "Leads", FILTER(Calendario, ...))

*(Nota: La nomenclatura `[Año]` y `[Año2]vs[Año1]` es un estándar que agrupa dinámicamente las medidas explícitas para 2024, 2025, 2026, etc. Toda variable en blanco maneja internamente un retorno de 0 o "--" para errores de división).*
